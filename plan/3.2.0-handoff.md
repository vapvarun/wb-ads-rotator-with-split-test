## 3. How to work on this code

- **One development branch at a time, plus `main`.** Commit straight to `3.2.0`. No
  `fix/*` branches; those exist only during a release cycle. A scratch worktree is fine
  for isolation, but push its commits to `origin/3.2.0` and delete the branch and
  worktree the same day. Never `git add -A` in a worktree (its `vendor/` is a symlink the
  ignore rule misses); add files by path.
- **Commits carry no AI attribution trailers.** Check `git log -1 --format=%B`.
- **Tests:** Pro's tests live in this repo under `tests/pro/`.
  `WBAM_RUN_PRO_TESTS=1 WP_TESTS_DIR=<tests lib> vendor/bin/phpunit --testsuite=free`
  (and `--testsuite=pro`). Use a copy of the WP tests library whose config points at its
  own database (`wbam_test_dev`), created on the wp-ads Local MySQL socket, because other
  projects share the default one and drop its tables mid-run. Run one suite at a time.
  The bootstrap loads Pro from the sibling `wb-ad-manager-pro` folder. Code that runs an
  SDK money call (`START TRANSACTION`/`COMMIT`) commits the test's transaction: insert
  fixtures directly or delete them in `tear_down`. Today: Pro 1058 tests, Free 387, each
  with one long-standing skip (`Test_Membership_Plans`, `Test_First_Run_Wizard_Handoff`).
- **Gates before landing:** both suites green, Pro `bin/release-gate.sh`, Free
  `bin/plugin-check-gate.sh` (0 errors), `bin/check-hooks-documented.sh` in each repo.
  **Run the Pro gate in a folder named `wb-ad-manager-pro` with the Free plugin next to
  it as `wb-ads-rotator-with-split-test`** (two detached worktrees with `vendor`
  symlinked, `WBAM_SDK_SRC` pointing at the SDK checkout). From the live plugin folder or
  a differently named folder it reports false PHPStan and Plugin Check failures.
- **Moving a card:** comment with the commits, root cause, proof and retest steps, then
  move it to Ready for Testing and read `parent.title` back. QA works from the cards
  (cards-only communication). A comment that overstates what a test proves gets a
  correction comment, not silence.
- **The live plugin folders are what QA tests.** Another session may hold uncommitted
  edits there. Never stash, reset or overwrite someone else's working-tree changes; ask.
  `wp db query` does not work here (socket); use `wp eval` / `eval-file`.
- **Browser checks:** the Playwright tool writes files into the site's document root
  (publicly served). Move them to `~/Local Sites/wp-ads/app/qa-artifacts/` and delete
  `.playwright-mcp` the same turn.
- **Dates:** store UTC, show and pick in the site time zone (Settings > General).
- **Words:** follow `docs/standards/glossary.md`: Balance and Add funds, never
  "Credits" or "Wallet" on screens; a seller's item uses the owner's label through
  `Settings_Helper::get_classifieds_label()`. `tests/pro/test-vocabulary-wave6.php`
  enforces it (it flagged a hard-coded "Listing packages" heading this session).
- **Settings:** plug-and-play. Rare technical options become filters; business
  controls stay settings.

## 7. Changed on 2026-09-28 (what a new session should know exists)

Shared helpers to reuse, not re-create:
- `Ad_Status::missing_setting()`, `draft_if_incomplete()` and `draft_notice()`
  (`includes/Core/class-ad-status.php`): an ad missing a required setting (AdSense
  without a Slot ID) is kept as a Draft with a reason, from the editor, REST, Abilities,
  Quick Edit and Bulk Edit. A live ad is judged only when a save changes its data or
  status, never on a plain rename.
- `Settings_Helper::format_matching_enforced( $context )`: the one answer, and the one
  place that fires `wbam_enforce_format_matching`. Render, editor, save, the Pro package
  guard, the Pro submission check and the portal wizard all ask it. Format Matching is
  off on wp-ads, so turn it on to see format refusals.
- `Ad_Status::editor_hint()`: the admin-only note for an empty shortcode or block, and
  for an id with no ad behind it.

By card (all on `3.2.0`):
- REST `POST /ads` honours `status`; REST and Abilities return a `notice` when an ad is
  kept as draft (card `10345316057`, `10345203271`).
- `[wbam_ad]` and the `wb-ads/ad` block show editors a hint when empty
  (`10345203531`).
- Pro: `submit_ad()` refuses a size format the package does not allow (error
  `wbam_format_not_in_package`), only when Format Matching is on. Allowed formats are
  size formats (leaderboard, medium-rectangle), not creative types (`10345352674`).
- Pro: Settings > Emails has six family switches (new advertiser, ad paused or changes
  requested, campaign updates, classified submitted and expiry, marketplace activity,
  membership changes). Each sender passes its key to `Email_Notifications::deliver()`;
  a missing key means on. Account suspended, banned and reactivated, membership renewal
  and payment failed, and buyer-seller messages stay always on (`10345203548`).
- Pro: the Full-mode classifieds extras (Custom Fields, Reviews, Messaging) are in the
  catalog; the surface check passes in Full mode (`10345243172`).
- Pro: owners edit classified listing packages under Settings > Classifieds
  ("Classified packages", named after the item label). Read through
  `Classified_Manager::get_listing_packages()`; the starter set is 30 days $0, 60 days
  $5, 90 days $15 and is only used until the owner saves a list (`9757961331`).

  "1 post updated"; the reason shows only on that ad's edit screen.
- A starter package card reads "30 days, Free, Stays up for 30 days" (length twice).
